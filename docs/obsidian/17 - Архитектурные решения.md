# Архитектурные решения

Эта заметка хранит не только результат, но и причины принятых решений.

## Решение 1. Выделить источник данных

**Контекст:** старый `RealtimeWasserfall` сам читал файлы.

**Решение:** вынести получение IQ и metadata в отдельные классы источников.

**Причина:** математический блок не должен знать, откуда пришли данные.

**Следствие:** в будущем файловый источник можно заменить сетевым.

Связанные заметки: [[01 - Архитектурная цель]], [[04 - Контракт источника данных]].

## Решение 2. Делать выбор источника в Configurator

**Контекст:** программе нужен выбор между режимами.

**Решение:** выполнять `switch` по типу источника в одном конфигураторе.

**Причина:** выбор реализации является задачей сборки приложения, а не обработки данных.

**Следствие:** условные конструкции не размазываются по pipeline.

Связанная заметка: [[05 - Configurator]].

## Решение 3. Разделить recorded- и realtime-источники

**Контекст:** два режима используют одинаковый формат файлов, но по-разному обходят metadata.

**Решение:** создать два конкретных класса.

| Recorded | Realtime |
|---|---|
| Читает с начала | Ждёт свежую строку |
| Сохраняет порядок | Может пропускать историю |
| EOF завершает работу | Отсутствие строки означает ожидание |
| Не удаляет запись | Может выполнять очистку |

**Причина:** это разные политики с разным смыслом, а не один параметр алгоритма.

## Решение 4. Вынести общее чтение IQ в родителя

**Контекст:** оба источника одинаково читают `.cf32`.

**Решение:** создать абстрактный [[23 - Source - FileDataSource|FileDataSource.m]] и разместить общий `readIQ()` в нём.

**Причина:** общий механизм должен иметь одно место изменения.

**Следствие:** наследники концентрируются на своей политике metadata.

## Решение 5. Сделать readIQ protected

**Контекст:** чтение IQ нужно наследникам, но не внешнему pipeline.

**Решение:** использовать:

```matlab
methods(Access=protected)
```

**Причина:** публичный интерфейс источника должен быть маленьким.

## Решение 6. Объявить nextData абстрактным

**Контекст:** любой конкретный файловый источник обязан выдавать данные.

**Решение:** добавить обязательный метод без реализации:

```matlab
[iq_complex, metadata] = nextData(obj);
```

**Причина:** неполный наследник должен обнаруживаться сразу при создании объекта.

## Решение 7. Не создавать общий DataSource заранее

**Контекст:** позже появится сеть.

**Решение:** рассматривать `DataSource` как следующий уровень иерархии, но добавлять его вместе с первым сетевым источником.

**Причина:** промежуточный класс должен приносить реальный контракт или общий механизм.

Подробнее: [[12 - Переход к сети]].

## Открытое решение. Realtime-очистка

Массовое удаление `*.cf32` слишком широко. Требуется определить точную стратегию удаления обработанных и пропущенных файлов.

Подробнее: [[10 - Жизненный цикл файлов]].
